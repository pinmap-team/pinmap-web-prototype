# 핀맵 웹 프로토타입

핀맵은 SNS에서 저장한 콘텐츠를 다시 찾고, 콘텐츠에 나온 장소를 지도에서 살펴보는 모바일 웹 프로토타입입니다. 이 저장소의 `main`은 [공식 핀맵 화면](https://pinmap-prototype.vercel.app/)에 연결되어 있습니다. 사용자경험디자인II (26-2) 팀 프로젝트입니다.

저장소 루트에는 **예시 콘텐츠를 둘러보는 프로토타입**, **로그인 없는 빈 개발 화면**, **Supabase 로그인 화면과 계정용 개발 화면**이 있습니다. 예전 화면 복사본은 Git 기록에서 확인할 수 있습니다. Instagram 분석 API는 별도 [Pinmap 백엔드 저장소](https://github.com/pinmap-team/pinmap-backend)에서 관리합니다. 분석과 저장은 로그인한 공식 핀맵 화면에서 시험할 수 있습니다.

## 시작 환경과 데이터

루트 주소를 열면 시작 환경을 선택합니다. `index.html`은 402 × 874 크기의 앱 프레임이고, 화면과 동작은 프레임 안의 `app.html`에 있습니다. 직접 URL을 열 때도 `index.html?mode=...` 형식을 사용하세요. 새로고침하면 시작 환경 선택으로 돌아가며, 이는 브라우저에 저장된 데이터를 지우는 동작은 아닙니다.

| 시작 화면 | 현재 동작 | 데이터 보관 |
| --- | --- | --- |
| **프로토타입 체험** (`mode=prototype`) | 예시 콘텐츠 13개로 홈, 저장함, 지도, 상세, 코스, 설정을 체험합니다. 링크 저장과 SNS 공유 흐름은 화면 시연이며 `AI 자동 분류`는 간단한 규칙입니다. | 콘텐츠·설정·코스를 해당 브라우저의 `localStorage`에 저장합니다. |
| **로그인 후 개발 화면** (`auth.html?screen=welcome` → `mode=development&auth=required`) | Supabase로 로그인한 뒤 Instagram 링크에서 장소와 전시·팝업 일정을 분석합니다. 장소는 지도에, 행사는 상세와 캘린더에 표시합니다. | 백엔드의 `content-save` API와 계정별 DB 저장소가 배포·설정된 경우 링크와 추출 결과를 계정에 저장하고 새로고침 후 다시 불러옵니다. |

예시 프로토타입의 브라우저 저장 데이터와 로그인 없는 개발 화면의 결과는 서로 섞이지 않습니다. 두 화면의 데이터는 다른 기기와 동기화되지 않습니다. 계정용 개발 화면의 링크와 추출 결과는 별도 DB에 계정별로 보관하며, 서버 준비가 끝나기 전에는 저장 실패를 표시합니다.

## 구현된 화면과 기능

- **시작과 탐색:** 온보딩, 관심사에 따른 홈, 검색, 저장함·모음·폴더, 콘텐츠 상세, 캘린더, 마이페이지, 라이트·다크 화면 모드.
- **콘텐츠 저장:** 우하단 `+`에서 Instagram ZIP, 게시물 링크, 캡처 화면을 고릅니다. 로그인한 계정에서 Instagram 저장 게시물 ZIP(최대 40MB)의 `saved_posts.json`을 기기에서 읽어 중복 링크를 제외하고 기존 분석·저장 API에 한 건씩 전송합니다. 진행 상황은 브라우저에 보관해 새로고침 후 같은 계정으로 돌아오면 이어서 처리합니다. 월간 분석 한도 또는 계정 저장 100개 한도에 닿거나 요청 오류가 발생하면 일시정지하고, 가능한 때 이어서 처리할 수 있습니다. 브라우저 탭을 닫은 동안에는 분석이 진행되지 않습니다. 로그인한 계정의 캡처 화면은 JPEG로 축소해 서버에 전송하고 이미지의 장소·일정·설명을 분석해 계정에 저장합니다. 프로토타입과 로그인 없는 화면에서는 ZIP·캡처를 선택할 수 있지만 분석·저장은 로그인 후 사용할 수 있습니다. 링크를 저장한 뒤 상세 화면에서 제목, 분류, 모음, 메모를 수정할 수 있습니다. 프로토타입 저장은 브라우저에만 남으며 장소·일정 서버 분석을 실행하지 않습니다. SNS 공유 시연은 실제 Instagram 저장 목록을 자동으로 가져오는 기능이 아닙니다.
- **장소 지도:** 저장한 장소의 사진 핀과 카드 캐러셀, 카테고리 필터, 저장 장소 우선 검색과 OpenStreetMap/Photon 외부 장소 검색, 현재 위치·직접 핀 찍기 흐름을 제공합니다. 지도 카드의 주소를 누르면 같은 지도에서 해당 위치로 이동합니다.
- **지도:** 구글 지도만 사용합니다. 브라우저용 구글 지도 키가 필요하며, 연결에 실패하면 오류를 표시합니다. 장소 핀과 저장 데이터는 유지됩니다.
- **코스:** 게시물 안에서 지도 위치가 확인된 장소를 각각 경유지로 골라 단일 목록 코스를 만들고 저장·재편집합니다. 한 게시물의 여러 장소도 따로 추가할 수 있습니다. 기존 여러 날짜 코스는 순서를 유지해 한 목록으로 읽으며 중복 장소는 한 번만 표시합니다. 코스는 프로토타입에서 브라우저에, 로그인 화면에서 계정에 저장합니다.
- **즐겨찾기와 계정 저장:** 지도 카드·장소 상세·즐겨찾기 목록의 하트는 게시물이 아닌 개별 장소에 연결됩니다. 한 게시물에서 한 장소의 좋아요를 취소해도 다른 장소의 좋아요는 유지됩니다. 프로토타입은 브라우저에, 로그인 화면은 계정 메타데이터 `pinmap_favorites`에 장소 키를 저장합니다. 기존 게시물 단위 좋아요는 해당 게시물의 지도 장소들로 옮겨 읽습니다. `auth.html`의 이메일·카카오·구글 로그인은 Supabase와 연결됩니다. 인증된 계정은 링크 분석과 저장, 목록 복원, 개별·선택 삭제를 백엔드 API로 처리합니다. 이 기능은 아래 데이터베이스 이전과 백엔드 배포가 완료돼야 사용할 수 있습니다. 계정의 폴더 생성·담기·삭제는 Supabase 사용자 메타데이터 `pinmap_collections`에 저장합니다. 콘텐츠 원문·추출 결과는 기존 콘텐츠 데이터베이스에 유지하며, 폴더 삭제는 콘텐츠를 지우지 않습니다. 계정의 메모·프로필·지도 직접 핀·콘텐츠 수정도 계정 메타데이터에 저장합니다. 프로토타입과 로그인 화면은 동일한 수정·핀 추가 화면을 쓰고 저장소만 다릅니다.

지도 배경을 표시하려면 브라우저용 구글 지도 키가 필요합니다. OpenStreetMap/Photon은 장소 검색에만 사용합니다. Instagram 장소 이름의 좌표를 찾는 온라인 분석은 아래의 별도 서버 경로를 사용합니다.

## Instagram 장소·일정 추출 테스트

1. [공식 핀맵](https://pinmap-prototype.vercel.app/)에서 로그인한 뒤 계정용 개발 화면을 엽니다.
2. Instagram 게시물 또는 릴스 링크를 저장하면 백엔드가 장소와 행사 일정을 분석하고 결과를 계정에 저장합니다.
3. 좌표가 있는 장소는 지도 핀으로, 좌표가 없는 장소는 게시물 상세의 확인 필요 목록으로 표시합니다. 확인된 행사 날짜는 상세와 캘린더에서 볼 수 있습니다.

로그인 없는 빈 개발 화면에서도 링크를 직접 붙여넣어 장소만 분석할 수 있습니다. 이때 테스트 코드는 브라우저 세션에 입력하며 URL에 포함하지 않습니다.

응답에는 게시물 제목·AI 요약·작성자 아이디·프로필 사진(수집 가능한 경우)·대표 표지·장소별 이름, 주소, 좌표 및 확인 상태가 포함될 수 있습니다. **좌표가 있는 장소만** 지도 핀으로 표시되어 추출 장소 수와 지도 핀 수가 다를 수 있습니다.

로그인한 화면은 백엔드 저장소의 `POST /api/content-save`를 호출합니다. 로그인 없는 개발 화면은 테스트 코드를 확인하는 `POST /api/place-extract`를 호출합니다. 백엔드는 분석 요청을 Cloud Run 서버로 전달합니다. API 함수, 미디어 수집, AI 분석, 지도 후보 검색 코드는 모두 백엔드 저장소에서 관리합니다. 이 웹 저장소는 화면과 API 연결 경로만 유지합니다.

로그인 없는 테스트는 **장소 관련 Instagram 링크**를 전제로 합니다. 계정용 화면은 장소와 전시·팝업 행사를 별도 항목으로 추출하며, 연월일이 확정된 행사 시작·종료일만 캘린더에 후보 일정으로 표시합니다. 날짜·장소는 원본에서 확인해야 합니다. 일반 카테고리 자동 분류와 사용자의 Instagram 저장 목록 자동 가져오기는 이 흐름에 없습니다. 비공개·로그인 필요·접근 제한 게시물은 원본을 수집하지 못할 수 있고, 장소명만으로 고른 지도 후보는 실제 영업 위치와 일치하는지 확인해야 합니다.

## 로컬 실행

저장소 루트에서 정적 화면을 실행합니다.

```sh
python3 -m http.server 8093 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8093/`을 엽니다. 이 정적 서버는 `/api/*`를 제공하지 않아 실제 로그인·외부 지도 키·장소 추출은 확인할 수 없습니다. 기본 지도는 사용할 수 있습니다.

로컬에서 로그인 설정 API와 지도 설정 API를 시험하려면 Node 20.12 이상에서 다음 서버를 실행합니다.

```sh
node scripts/dev-auth-server.cjs
```

기본 주소는 `http://127.0.0.1:8095/`입니다. 이 서버는 백엔드의 공개 인증·지도 설정 API를 프록시합니다. Instagram 추출은 공식 배포의 로그인 테스트 화면에서 확인하세요. OAuth를 로컬에서 시험한다면 Supabase와 각 공급자의 허용 URL을 실제 로컬 주소·포트에 맞춰 설정해야 합니다.

## 공개 화면 접근

공개 앱은 프로토타입과 로그인 테스트만 제공한다. 로그인 없는 `mode=development` 단독 주소와 `place-test` 주소는 시작 화면으로 돌아간다. 인증이 필요한 `mode=development&auth=required` 경로는 실제 로그인 확인을 유지한다.

`screen-policy.js`에 현재 사용하는 화면만 등록한다. 옛 `placeset`·`accountaccess`는 현재 위치 편집·계정 관리로 연결하며 알 수 없는 화면은 홈으로 보낸다. 사용 종료한 SNS 공유 체험·모의 권한/푸시·익명 분석 미리보기·당겨서 새로고침 코드는 삭제했다. 기록은 Git 이력에서 확인한다. 회원 탈퇴의 미구현 확인·실행 버튼은 노출하지 않고 계정 삭제 문의를 제공한다.

## 온라인 연결

웹의 `vercel.json`은 `/api/auth/config`, `/api/map-config`, `/api/place-extract`, `/api/content-extract`, `/api/content-save`를 별도 백엔드 Vercel 프로젝트에 전달합니다. API 키와 추출 서버 설정은 [백엔드 저장소](https://github.com/pinmap-team/pinmap-backend)의 배포 환경에서 관리합니다. 계정 저장을 사용하려면 백엔드 저장소의 `database/001_content_extraction_quota.sql` → `database/002_saved_content.sql` → `database/003_developer_test_quota.sql`을 같은 Supabase 프로젝트에 순서대로 적용하고, 백엔드 Vercel에 서버 전용 `SUPABASE_SECRET_KEY`를 설정한 뒤 분석 서버·백엔드·웹을 배포해야 합니다. 비밀 키는 웹 저장소·브라우저에 넣지 않습니다. GitHub 코드 반영만으로 DB 표가 자동 생성되지는 않습니다. 인증된 행사 저장 흐름은 `?mode=development&auth=required`에서만 켜지며, 기본 시작 화면과 프로토타입 체험에는 적용되지 않습니다.

`main`에 병합하면 연결된 Vercel 프로젝트가 자동 배포됩니다. 공개 화면과 GitHub Actions 결과를 함께 확인하세요. 지도 제공자의 도메인 인증, Supabase 공급자 설정, Instagram 원본 접근 가능 여부는 코드 배포 성공과 별도로 확인해야 합니다.
