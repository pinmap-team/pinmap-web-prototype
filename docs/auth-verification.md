## 후속: 간단한 소개 + 로그인 선택 화면

사용자의 새 레퍼런스로 첫 화면을 단색 소개·핀맵 심볼·하단 카카오/이메일 선택 패널로 바꿨다. 이메일 입력창은 선택 후에 표시한다. 가상 인증 브라우저 검사도 첫 화면 선택 단계를 포함하도록 조정했다. 최신 화면은 `auth-simple-qa/welcome-mobile.png`, 이메일 입력은 `auth-simple-qa/signin-mobile.png`에 기록한다. 실제 계정 인증 완료 여부와는 구분한다.

## 후속: 세 가지 시작 환경 선택

- 루트에서 개발 테스트(로그인 없이 빈 데이터), 프로토타입 체험(기존 예시 13개), 로그인 테스트를 선택한다.
- 일반 개발/프로토타입 진입에는 인증 API 호출과 로그인 게이트가 없다. 로그인 완료 후 명시적 `auth=required` 경로에만 세션 확인을 적용한다.
- 로그인 테스트 카드는 기존 세션이 있어도 선택 화면을 보여주며 새로고침해도 확인할 수 있다. 일반 인증 콜백의 세션 복원·앱 복귀는 유지한다.
- `node --test tests/*.test.cjs`: 60개 통과. 세 카드 이동과 키보드 포커스, 빈 데이터/예시 데이터 분리를 별도 브라우저에서 확인했다.
- 최신 캡처는 `auth-entry-qa/entry-mobile.png`. 실제 계정/메일을 생성하지 않은 가상 응답으로 인증 흐름도 재검사했다.

## 후속: 회원가입·메일 확인·로그인 연결

사용자가 실제 카카오 로그인 성공과 인증 메일 수신을 확인했다. 이메일 가입 후 전체 로그인 완료는 아직 사용자 확인 전이다.

가입 입력 라벨·비밀번호 조건·확인 피드백을 보강하고, 가입 성공 응답 후 인증 메일 확인 화면으로 이동한다. 이메일 수정, 재발송, 60초 재발송 대기, 새로고침 시 대기 상태 복원, 이메일을 유지한 로그인 이동을 검증했다. 미인증 비밀번호 로그인은 인증 안내로 연결한다. PKCE verifier가 없는 다른 브라우저의 이메일 링크에서도 수동 비밀번호 로그인을 제공한다. 실제 비밀번호로 서버 인증이 성공한 경우에만 앱으로 진입한다.

검사: 자동 검사 60개 통과. 가상 Supabase Auth 응답을 사용하는 브라우저 검사에 새 메일 확인·재발송·다른 브라우저 링크 후 로그인 경로를 추가했다. 실제 회원 생성이나 메일 발송을 자동으로 수행하지 않았다. 최신 자료는 auth-signup-qa에 기록한다.
